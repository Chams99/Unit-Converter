# Universal Convertal UI, UX, and runtime audit

**Date:** 2026-10-04
**Scope:** first-release implementation in `D:\1_DEV\1_NEXT_JS\simple-units`
**Status:** frozen production build, UI matrix, API smoke checks, and local performance capture completed.

This report records the shipped English-only first-release behavior. The proposed French locale and later worker or database architecture remain roadmap decisions, not implemented or verified capabilities. The detailed browser evidence and screenshots are in the [final UI audit](../audit-2026-10-04/final/README.md).

## Build and runtime evidence

The checked toolchain was Node.js 24.11.1, pnpm 11.25.0, Turbo 2.11.7, Next.js 16.3.8, React 19.3.0, and Playwright 1.63.0 with system Chrome. `pnpm install --frozen-lockfile`, `pnpm run typecheck` (four workspace tasks), `pnpm run lint`, and `pnpm run test` completed successfully. The test suite reported 23 passing tests. Lint retains one non-blocking Next warning for the intentional raw image preview element.

The final forced production build used `NEXT_DIST_DIR=.next-audit-final` and `CONVERTAL_API_URL=http://127.0.0.3:48789` with `pnpm exec turbo run build --concurrency=1 --force`. All four workspace build tasks passed. The web output is `apps/web/.next-audit-final`; its build ID is `oc7WH7RDYukmS7iIwKtx4`.

The UI matrix ran against the production Next server at [http://127.0.0.1:3000](http://127.0.0.1:3000), serving that isolated build. Its same-origin API rewrite targeted the local `tsx watch` API at `127.0.0.3:48789`. Browser image conversions and downloads therefore exercised the application rewrite plus the API source runner. No external currency provider was called; currency race and failure cases used deterministic browser route mocks.

Separately, the built API was started with Node 24 from `apps/api/dist/server.js` at `127.0.0.3:48790`. Its health endpoint returned 200, `/v1/units` returned 73 units, and `POST /v1/convert` returned the expected `1 meter → 100 centimeter` result. A synthetic 1×1 PNG multipart upload converted to a 44-byte WebP with a valid RIFF signature. This direct smoke check confirms the built API path independently of the browser matrix's `tsx` API target.

## UI and accessibility results

The final Playwright matrix covered five routes (`/`, `/currency`, `/developer`, `/images`, `/about`), light and dark themes, and widths of 320, 390, 768, and 1440 pixels. It recorded **343 checks: 335 passed, 8 skipped, 0 failed, and 0 errors**, with 46 screenshots (40 route/theme/viewport captures, five text-resize captures, and one interaction capture). The eight skips are the shared-footer assertions on standalone `/about`, which intentionally does not render that shell in this pass; they are not passing assertions. Browser evidence and machine-readable details are in [`final/README.md`](../audit-2026-10-04/final/README.md) and [`final/results.json`](../audit-2026-10-04/final/results.json).

One P2 design finding remains: `/about` omits the shared skip link, primary navigation, theme control, and footer. Keep that shell-consistency issue visible for follow-up. The matrix also verified local image conversions and downloadable outputs, error/retry behavior, mocked currency stale-response handling, keyboard and copy behavior, and no horizontal page overflow in the tested layouts.

The five enlarged-text checks changed root font size from 16px to 32px at a 390px viewport and retained a 390px document width. This is a root-font-size reflow proxy; it is not evidence from 200% browser zoom. Firefox and WebKit were unavailable. A complete WCAG 2.2 conformance review, screen-reader review, and every assistive-technology combination were not performed, so this is not a WCAG certification.

## Local lab performance

One performance scan ran after the UI browser session closed, against the same production web preview at `http://127.0.0.1:3000`. Conditions were headless Chrome, loopback target, no CPU or network throttling, one new browser context for each route and viewport, and a 1500 ms observation window. The raw eight-sample result is [`performance-final.json`](artifacts/audit-final-2026-10-04/performance-final.json).

| Viewport | Routes | FCP/LCP range | CLS | TTFB range |
| --- | --- | ---: | ---: | ---: |
| 390 × 900 | `/`, `/currency`, `/developer`, `/images` | 240–508 ms | 0 | 6.0–6.7 ms |
| 1440 × 900 | `/`, `/currency`, `/developer`, `/images` | 280–316 ms | 0 | 5.4–6.4 ms |

These local lab observations are below the web.dev reference thresholds for LCP (2.5 s) and CLS (0.1), but they are not field percentiles or a production-network forecast. INP was not measured; no p75 field claim is made. The older `performance.json` in the same artifact folder is historical baseline evidence, not the final run.

## Limits and references

The audit did not measure Firefox or WebKit, actual browser zoom, screen-reader behavior, full WCAG 2.2 conformance, field Core Web Vitals, production CDN behavior, sustained load or memory isolation, or a deployed service. Currency checks used mocks rather than a live provider.
